# Controlled Real Execution Dogfood

This dogfood note covers a docs-only task created from `task-intake` for controlled real execution.

## Lifecycle

1. Author the task through the deterministic `task-intake` scaffold.
2. Run draft validation and review the resulting draft.
3. Promote the reviewed draft into `tasks.yaml`.
4. Keep the promoted task at `enabled=false` until an operator explicitly enables it for execution.

This keeps the dogfood path conservative and does not weaken validation, review, apply, or safety gates.

## Execution Boundary

- Real `run-pipeline` execution must be started manually by a human from a normal Git Bash session.
- Do not launch the real pipeline from a nested Codex or VS Code agent session.
- Explicit enable is required before `doctor`, `dry-run`, or a real run for this task.

## Human-Governed Handoff After Run

After a successful run, handoff into the target repository remains human-governed:

`show-pipeline` / `show-run` -> `review-run --decision approved` -> `apply-run` -> `git diff` -> `python -m unittest discover -s tests` -> manual `git add` / `git commit`

Use `accept-run` only for an advanced, explicit delegated apply-plus-commit path. It is not the default flow for this dogfood task.

For the surrounding operator workflow, see [Operator Quickstart](../operator_quickstart.md) and [Manual Commit Workflow](../manual_commit_workflow.md).
